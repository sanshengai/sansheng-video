# Muse：入口适配卡与网页实测

本页只写 Meta Muse（muse.ai）这个生成入口和通用契约不一样的地方。一条镜头请求由哪几层、哪些字段组成见 [镜头请求契约](shot-request-template.md)；资产锁定、首帧闭环、三态核对、收片与返修流程见 [生成镜头](generated-shots.md)；电影感摄影语法与审美诊断见 [电影感与视听设计](generated-audiovisual.md)。下面是自然语言交接与网页实测，不是 Muse API schema；能力以当次实测为准。

## 适配卡

| 项 | Muse 网页的实际情况 | 依据 |
|---|---|---|
| 投递方式 | 没有公共 API，经已登录会话的浏览器自动化发消息；由 Muse 的对话模型替你逐条写视频提示词、调用视频工具 | 2026-10 实测 |
| 锁怎么传 | **逐镜完整重复但必须精简蒸馏（65–120 词）**。写在消息开头的规则不一定被对话模型带进每一条视频；开头只放任务、条数、只用前 7 秒、运动节奏与回复格式，规则精简后放进每个镜块。注意「对话 LLM → 视频模型」存在双层注意力稀释：I2V 首帧已锁定的户外时代/建筑大段描写与 `CUTS TO` 不得再灌进单镜文本，且同一镜不带 `choose from:` 或 `gasp/sigh/cheer/chant` 等声源诱发词。「记忆」功能可能混入别的项目设定，不依赖「照上一条」 | 2026-11 750 镜复盘 + DiT 注意力实证 |
| 参考图 | 图片只是提示条目，没有首帧、尾帧参数，也不区分角色。参考图的构图、光影与质感会压过文字。**必须先把电影感 4 决定（光/色/质/构）做进本镜首帧图**（走 `sansheng-image` `board`），作为该镜**唯一**一张图传入，按序号对应（第 k 镜 = 第 k 张附件）；定妆图只用来生首帧，中近景用 12–18 词固定英文短锚点，**航拍/大全景/纯背影不贴长外貌**。首帧只画 0 秒已在场的人 | 2026-10、11 实测 |
| 取用时长与节奏 | 视频 10 秒、1280×720、24fps；后半段常换天气、光线、建筑，剪辑默认只用前 6–7 秒。**两档节奏按镜选用**：① **连续平稳运动（`muse-i2v-continuous`，推荐默认）**——第 1 帧起持续 7–10 秒保持单一匀缓可见运镜或自然动作，`Ref Lock` 写 `keep scene, subjects and lighting consistent`（不锁死构图），消除第 4 秒后僵停的呆滞感；② **活照片 / 停稳单动作（`muse-i2v-still` / `muse-i2v-action`）**——仅用于需彻底定格的镜头（`0–4s` 动作、`4–10s` 停稳，或 `still` 人物冻结只动环境微动白名单） | 2026-11 多批复核与连续运动升级 |
| 运镜与用词 | 慢推、慢拉、横移、匀速航拍、升起、固定最稳；快速追逐、翻滚、俯冲改成慢动作加前景、风、布料表现速度。固定机位和「保持高度」都不可靠，写明稳定地平线或结束构图并在收片时必检；动态运镜镜不混写 `keep exact composition` | 官方发布说明点名的短板 + 实测 |
| 声音 | 原生单声道 AAC 24kHz，响度 −34～−18 LUFS，入片前统一；不要原生配乐，环境声和动作声保留作原声层 | 2026-10 实测 |
| 批量与额度 | 一条消息视频最多成功 6 条，建议每对话 3～4 镜；按 24 小时计视频额度，用完返回 `video_daily_budget_exhausted`（上游 429）。新号常只有一个主对话，多开标签页不能并行，要提速只能多账号各用独立浏览器 | 2026-10、11 实测 |
| 失败信号 | 「无法生成（原因）」、`integrity_check_failed`（不给原因）、内部错误无文件、发送后长时间无回复、不按首帧（首帧相似度很低）。审核拒绝后原样重发几乎不会成功，重发先改一个变量（降动作负荷为平稳慢推保底）；正面人脸近景连续被拦时，**优先更换景别与起点首帧图**（远景、侧面、背影、手部/器物特写）而非同图改同义词重试；无回复先暂停该号再试，不算镜头失败 | 2026-11 复盘 |

## 网页执行与回收

以下来自使用 Muse 网页版的实测（2026-10 至 2026-11），属于观察到的现象，不是 Muse 的能力承诺。

- **认准产品**：本页的 Muse 指 Meta 的 Muse（智能体应用 muse.ai，视频由 Meta Superintelligence Labs 的 Muse Video 生成；2026-07 以预览发布）。HeyGen Muse、Microsoft Muse 与第三方「Muse Video」网站都不是它，它们的经验与产出不记作 Muse 结果。官方未公开单段时长、分辨率、画幅或参考图能力，参数一律以实测为准。
- **官方承认的短板**：发布说明点名「音画同步」与「物理准确的快速运动」仍待改进。快速追逐、翻滚、俯冲改用慢动作与前景、风、布料表现速度；需要卡点的拟音收片后先听，不准就重生成或后期补。
- **入口**：网页版没有公共 API，通过已登录会话的浏览器自动化执行。连接哪一个浏览器实例、哪个账号由本机 profile 提供，不写进本仓。
- **同一账号是否能分对话并行**：先核实首发后有没有拿到 `/thread/` 地址；新号常只有一个主对话（停在 `https://muse.ai/`），多开标签页会串流错配，此时必须单路。要提速用多账号：每个账号独立 user-data-dir 和调试端口各开专用 Chrome。
- **发送后确认送达**：提交后等地址变成具体对话、且无「未确认送达 / 消息发送失败」才算发出；生成中不要切换或关闭发起标签页，否则可能 Interrupted。
- **生图每条消息最多 4 张**，无画幅参数，实际常返回 1920×1280（3:2）。参考图带偏视频画幅（附 3:2 图常返回 1152×768），故首帧图务必原生做成目标画幅（16:9 / 9:16），**不要两侧补纯色边**（色块会被画进视频）。
- **10 秒后半段易漂移**：默认只剪前 6–7 秒；可逆动作（拉弓放箭、搬起放下）容易做反，改成单向可停动作或纯运镜+环境微动。
- **不一定照首帧生成**：偶发与附图完全无关或重复字节两份，收片用首帧与附图做相似度核对，去重比对首帧指纹而非文件哈希。
- **一个对话只放 3～4 镜**：上下文过长会整批报错无文件；补拍开新短对话，完整带入精简锁句和首帧。
- **ZIP 下载与校验**：点击卡片后需再点预览面板「下载」按钮；不同批次可能同名，校验非 0 字节并用清单 SHA-256 核对原片。
- **`integrity_check_failed` 不返回原因**：保存原文、改中性动作/光线描写或降为平稳慢推重提一次；返修上限为每镜首次 + 最多 2 次，每次只改一处并并排对比。
