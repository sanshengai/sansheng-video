# 制作流程

## 职责与项目记录

本文件负责各阶段的交接与修订范围。宣传片、知识解释等 reference 负责各自的表达方法；素材与参考工具按镜头需求供给；原 timeline／EDL 负责可执行时间、素材和声音；渲染器不决定风格；验收分别保留技术结果、真实视听和用户反馈。

制作单 `brief.md` 记录目标与选择理由，镜头细节和音画事件进入原工程，不新建第二套导演清单或审批状态。已有 brief／treatment 的工程沿用原文件，按[制作单模板](brief-template.md)补缺项，不另写一份。新作按下面的依赖关系推进，可以围绕高风险片段回看前面的选择；局部修改不重走全链。

品牌从项目配置、显式 `SANSHENG_VIDEO_PROFILE_DIR` 或用户建立的本地 `profile/` 获取。素材库工具的相对路径按返回的 profile 根解析，媒体存储目录与工具目录分别取配置中的真实值。

## 1. 内容变成影片

| 项目 | 说明 |
|---|---|
| 输入 | 已校对内容、目标受众、用途、画幅和现有资源；已有工程的原制作单 |
| 产物 | `brief.md`，按[制作单模板](brief-template.md)；局部修改写[修订卡](#修订卡) |
| 进入下一步的条件 | `python3 scripts/check_brief.py PROJECT/brief.md --mode new\|continue\|series` 无缺项；需要作者判断的关键取舍已有反馈或授权 |
| 不满足时 | 补制作单缺项；作者否定时先分清是主张、结构、选材还是呈现方式，只改相应部分 |

读取已校对内容、目标受众、用途、画幅和现有资源。将文字材料整理成适合观看或听懂的视频表达：保留事实、因果、关键例子和落点，删去只适合阅读的枝节。不按 H2 一一生成镜头，不编造数据、亲身经历或证据。有旁白时由真实录音参与定时；无旁白不补写口播稿来凑流程，时长由表达和实际声音结构决定。

制作单写清观众看完记住的一句话、观看情境、开头 3 秒、结构与段落、视觉母题、声音意图、事实来源和已有素材。已有工程只记录本次变化，不反复重建全套说明。数字默认值与默认不用的套路见[数字默认值与套路清单](craft-defaults.md)，偏离时在「自主决定」写一句理由。

同时确定观看情境与希望产生的感受：吸引继续看、解释关系、建立信任或促成行动，哪一个是主线。把“高级、克制、有气势”等要求落实为具体变化与注意力安排，再选择字体、色彩和速度；不直接套成低饱和、细字、慢推镜或密集卡点。已有片得到认可的部分先明确保留，未知处才探索。

竖屏信息流平台（profile 的 `delivery.feed_platforms`）默认要求开头 3 秒静音也能看懂：观众刷到时多半没开声音，前 3 秒看不出讲什么就划走了。剧情片、横屏长视频等不靠前 3 秒留人的片子，在制作单写豁免和一句理由即可，不另走审批。

新产品首发、功能宣传或品牌片，按[宣传片方法](promotion-film.md)从真实产品动作与成果推导信息结构、视觉语言和声音；不将宣传片的节奏套入对白或教学片。自己已有方案时保留，只补当前缺失的推导。知识、城市／历史或角色系列讲解按[知识解释与系列表达](knowledge-explainers.md)，将一个问题展开为可追踪的关系或状态变化；它补充原镜头设计，不增加逐句切镜或另一套制作表。

### 前期与作者共同定方向

前期由 Agent 做研究、归纳和筛选，作者贡献创作意图、核心受众经验与审美取舍。先查产品／内容所属资料、已有卖点总结、旧片反馈和真实成果，已有答案不重新问。不要从最容易做的动画倒推影片要说什么，也不要让作者先填一份完整问卷，更不要把海量筛选工作交回作者。

向作者呈现一份可直接纠正的简短制作提案，内容取自制作单：

- **核心**：给谁、在什么观看情境下看；这几十秒最想让他记住的一句话是什么；用什么真实证据支撑、希望看后做什么。说明推荐这个角度的理由。产品有多个优点时先查全，再决定本片主次和暂不讲的部分；一片可以串联多个优点，但须共同服务清楚的主线，不能遗漏后装成有意取舍。
- **结构**：按实际内容列出少量段落，说明每段讲什么、观众具体看什么、怎样推进核心与落到结尾。时间先给大致范围，待真实声音和动作校准；不提前精修全片分镜，也不靠固定段数套所有作品。
- **视觉**：用实际候选素材、代表性首帧或既有片段说明选图、构图、材质和运动会是什么样。先自行排除不符内容、质量或使用条件的候选；审美尚无依据时，给一个推荐方向与少量真正有差异的备选，讲清差异以及各自更适合的受众感受。不要只报风格名、形容词或展示上游漂亮示范，隐藏本片实际要用的图；开篇与承担卖点证据的画面优先呈现。

围绕未定之处问容易回答的问题，例如“这组开篇作品像不像你愿意用来代表自己的作品？”“更想吸引被画风打动的人，还是急着解决内容配图问题的人？”问题须针对当前提案，不预设所有作者的偏好相同。Agent 负责事实、可行性和筛选依据，作者决定个人审美和受众取舍；动效数量、技术检查或模型好评都不能代替作者认可。

以便于比较的最低成本呈现：简短文字加真实图片、并排预览通常足够；需要批量选择、分组或导出时再做交互看板，遵守宿主的看板约定。看板是协作载体，数量不代表前期质量。音乐与音效同时说明角色及已有认可依据；若它们决定全片气质或节奏，再给实际可试听片段比较，不能宣称未听过的素材已获认可。

作者确认节点按任务分档：

- **新方向、逐镜生成的高成本短片**：按[电影感生成短片](cinematic-generated-film.md#3-制作顺序每道关卡过了才花下一笔额度)的关卡，在视觉圣经、静图版、画风小样与粗剪处请作者判断，因为每过一道关卡才花下一笔生成额度。
- **其余新作**：只在核心主张、整体结构或会牵动全片返工的视觉方向仍需作者判断时，先取得反馈再进入完整制作；等待期间可做资料核对、候选整理与可逆的技术探针。
- **局部修改、沿用认可的系列规范，或作者已授权自行决定**：记录采用依据与尚存假设后继续，不确认。

一项任务同时落入几档时取较高的一档；作者明确说某个节点不用确认的，可以跳过，并写进制作单「自主决定」。

只问未解决的关键问题；作者的一次反馈可以同时确定几项，不强拆成多轮关卡。选定与舍弃的理由、作者原意和适用范围记回原制作单；仅在作者明确适用时沉淀为跨项目偏好。

## 2. 镜头设计

| 项目 | 说明 |
|---|---|
| 输入 | 制作单；已有素材与 profile 精选库 |
| 产物 | 每镜稳定 ID、目的、起态、变化、稳定期和声音决定；素材候选与缺件清单 |
| 进入下一步的条件 | 每个镜头都有可取得的画面和明确的声音决定（原声、补音或有意安静） |
| 不满足时 | 缺画面回看制作单的段落表和选材；声音未决就补决定，不写空计划 |

让画面解释内容：对象之间发生什么变化、为什么变化、观众如何看懂。不要默认把文章逐段变成大标题和字幕页；也不为追求运动牺牲阅读与理解。

新作缺少视觉方向，或某个镜头需要笔触、材质、摄影机实现时，按 [Lemo 风格与实现](lemo-opuscar.md) 查最多 3 个候选，选一个主风格；先写自己的内容和镜头，再读示范代码。已有工程局部修改不重选风格。

每镜明确稳定 ID、内容目的、起态、注意对象、变化、稳定期、起止时间、旁白／字幕及声音事件。先判断观众需要看见什么动作、关系或结果，再按 [资源配置](assets-and-profile.md) 核对已有素材和缺件；用实际候选修正构图、运动和可行性，不能让最容易取得的几张图包办全片。素材与镜头可以协同迭代，不把尚未取到的画面写成已具备。

场景声音在这里决定：现有原声是否足够、需要补什么，或为何留白；连续场景可共用一个决定，不另抄一份时间表。未决定和有意安静要分清，空计划不能代表已做决定。至少为主概念寻找物体、空间关系或因果动作的表达，而不是把句子换成大字卡。避免用固定镜头配比、转场密度或总时长比例替代判断。

声音沿原事件标明角色、突出程度及原因：关键动作需要观众听见，背景细节或远处声音可以克制。原声中已有的关键动作也要标在对应事件，不能只审后加音效；HTML 字段与实际执行见 [生产事件与工具](events-and-tools.md)。

全片选一个能够持续变化的视觉母题。用对象连续、相机移动、视线和动作衔接推进；文字进入后给够读完的停留（在时间线的 `reads` 里记录），复杂画面降低同时出现的信息量。新方向可做必要的内部动作验证；动作可行不代表选材已符合作者审美。已有方向与局部修订不增加样片关卡。

已有自己的方案，仍需要段落组织、对象连续或音画编排参考时，按 [视频案例参考](opus-video-cases.md) 查少量案例，提取适用机制再重写。没有合适结果继续自行设计；一次查询解决问题就不再遍历其他库，案例不改变项目引擎、声音来源与用户方向。需要新的运动表达时按 [动效与音效](motion-and-sound.md) 检索；先定表达目的再选用，不把每个动效都配上音效。

## 3. 按声音角色确定真实时间

| 项目 | 说明 |
|---|---|
| 输入 | 镜头设计；真实旁白或对白、选定的音乐 |
| 产物 | `timeline.json` 或 EDL：镜头、事件、字幕、声音决定、阅读停留 |
| 进入下一步的条件 | `production_timeline.py validate` 通过（制作时再 export／check）；`check_readability.py` 的提示已处理或在制作单写了理由（命令见[生产事件与工具](events-and-tools.md#可读性与成片测量)） |
| 不满足时 | 字幕太快就拆条或延长；文字停留不够就延长镜头或减少同屏信息；声音缺件回到第 2 节 |

先分清旁白／对白驱动、音乐驱动、场景动作驱动或有意无声。它们共用原时间源，但不能一律按文案均分时长，也不把所有片强行卡点。

需要新增配音时按 [TTS 选型与制作](tts.md) 固定声线、分块合成并导入真实块边界；已有录音不重配。

有旁白时先取得连续、可用的真实音频，再用实测时长安排镜头；保留音色和来源。项目已有原声默认保留，替换必须明确。无声作品声明无声，不补假音轨。

字幕、强调、动画和音效使用同一时间源。可靠锚点未知时用句级节奏并标记估时；不要平均分词后冒称逐词对齐。长句字幕可拆，但拆分时间的证据等级不能高于来源。

有对白时先稳定对白基准，再按剧情安排配乐、环境声和动作音效，不逐镜强配。关键动作需在同期背景中清楚可闻；必要时让相关背景在动作前后短暂、平滑地降低，保持台词清楚并避免突发刺耳。先调声部关系，不靠全片一起增益解决某个短音效被淹没。技术合成音床不等于合适的音乐，峰值和全片响度也不等于局部听感。

生成片段按 [视听设计](generated-audiovisual.md) 区分对白、连续环境、动作拟音和音乐。先检查原声中的有效声音，把需保留的环境和动作区间沿原时间源交给实际降噪／门控；字幕外或无对白不等于噪声。核对处理链实际保留了哪些区间，并比较相同源区间处理前后的声音与最终混音。源声不足时先判断是否适合补音或局部处理，不盲目放大全轨，也不直接关闭整集门控。声音事件沿既有时间源进入最终混音。

需要新增音效或配乐时，先按 [资源配置](assets-and-profile.md) 保留合适的项目声音，并查询当前 profile 显式启用的精选库；缺件再按需寻找在线来源，音效执行 [Openverse 音效流程](openverse-sfx.md)。音乐驱动的新方向在少量有实质差别的候选中比较实际可用乐段的进入、推进、转折和收束，再安排镜头与关键动作。已有用户指定或认可且适用的音乐不为凑候选而重选。返回一首只说明筛选结果，不证明它最合适；换一首也不等于音画结构已经改变。

选用依据写在原制作单，采用文件、区间、派生处理和来源接素材锁与原时间源，不再抄一张音乐时间表。没有实际听到就将适配判断标为待听，不依据曲名、标签、BPM 或响度冒称试听。无适合的声音可保留留白；不为完成清单硬加音效。

## 4. 制作与修订

| 项目 | 说明 |
|---|---|
| 输入 | 通过检查的时间源；锁定的素材与声音 |
| 产物 | 风险片段（新方向）→ 全片成片与渲染回执；局部修改的新版本 |
| 进入下一步的条件 | 风险片段证明开篇、关键交接和音乐成立；计划声音全部入轨；全片能连续播放 |
| 不满足时 | 按下面的回退规则回到受影响的素材、动作、声音或时间源 |

新方向在全片精修前，用实际选中素材、排版、动作和拟用声音验证最不确定的片段：开篇能否吸引，内容变化能否看懂，关键交接与音乐是否成立。可以只做一个能覆盖风险的连续片段，不设统一长度、数量或额外用户审批；已验证的方向、局部任务不重复做样片。预览仍通过原工程和实际支持的预览／渲染入口，不另建与成片脱节的演示页。若没达到目的，回改相应素材、动作或声音后再扩展；静帧好看不能代替连续效果。

样片供作者判断整体节奏或冲击力时，应带上关键动作所需的声音及与配乐的关系，不能只铺背景音乐就当成完整音画效果。动作音与画面一起设计，不默认留到选曲后再考虑。若当前只比较配乐，交付前明确说明“配乐试听，动作音效未完成”，反馈只归于选曲；音乐选定后继续补齐相应音画关系。原声已足够或有意留白的段落仍按原决定，不为每个动效强配声音。

采用已核对适用的项目素材；新声音按上一节的来源顺序选用，其他缺件按用途通过 [在线画面素材](stock-footage.md) 找通用 B-roll，或生成概念素材。真实产品、人物和现场证据使用真实来源，生成画面不得冒充事实。

代码镜头沿唯一默认 HyperFrames 链制作，真实媒体用 FFmpeg／EDL，其他引擎的既有镜头输出媒体后合流。编码前让实际装配器对上场景决定、锁定音源和实际轨道：计划补音却无事件、只取了素材未入轨、音源/区间不符、零音量或不支持的声音类型均须先修；不能用默认空数组继续并当作通过。通用 HTML 工具的检查和旧工程迁移见 [生产事件与工具](events-and-tools.md)；自有装配器在自己的计划/EDL 消费处实现同样的核对，不强制迁移引擎。先保证全片叙事、动作和声音可连续播放，再精修材质与细节。复杂效果不能靠叠加装饰掩盖内容问题。

问题按时间点和影响层记录：内容、时序、版式、素材、声音或渲染。只修受影响部分，并检查边界和最终装配。重建时间数据后重建其消费者，不手改派生产物；旧输出和证据保留，不覆盖冒充同一版本。

回退由实际依赖决定：主线变化回看镜头、素材和声音结构；换素材回看含义、裁切、动作及接缝；换音乐或采用区间回看音乐锚点、镜头时序和混音；改切点重建相关音画事件；只改角标或文字则保留不受影响的选择与有效证据。不能把“局部修改”当作不重建受影响消费者的理由，也不能每次反馈都从风格检索重来。

同一作品制作横竖版、或需要保留已认可部分做局部修订时，读 [多画幅与局部反馈](multi-aspect-revisions.md)。按目标画幅重排真实素材，共享事实和合适的声音；作品接力、画风展开、色系切换按信息目的选用。

反馈绑定当前版本、时间和可定位对象；“更自然”须回到具体段落检查，不能直接推断是模型问题。先复现观察，再区分已证实缺口和待检验原因，修后保留同位置前后证据。实际批注、工具模拟、作者观察和用户意见分别记录。

### 修订卡

局部修改和扩片每处改动写一张卡，放在工程的修订记录里：

| 字段 | 填什么 |
|---|---|
| 范围 | 时间码、镜头 ID、元素 |
| 必须不变 | 范围外的画面、声音、字体、版式；已认可组合中的相关项 |
| 现状 | 当前版本哪里不对，附时间点 |
| 目标 | 改完应是什么样 |
| 禁止的捷径 | 放大画面、移镜头、过度锐化、换风格、加光晕等掩盖问题的做法 |
| 证明 | 范围内看哪几帧；范围外用 `compare_frames.py` 证明没变。渲染前先写比对方法（哪组时间点、哪个范围），渲染后补上结果；没补结果之前标「待渲染后补」 |

多张卡逐张做，结构和运动先于表面细节。改动牵动时间源时，按上面的回退规则重建受影响的消费者，不能只改卡上写的那一处。

### 封面与首帧

面向发布的新视频都要有与内容相符的封面，短、中、长片同样适用；作者已选的样式持续有效。首帧必须是完整构图，不能是黑场、半透明过渡或待入场的空画面。设计或修改按[封面与首帧](video-covers.md)执行；局部改音等无关任务不重开封面流程。

### 系列与批量扩展

1. 在制作单「系列范围」列出本次包含的全部影片，写明旧片是否纳入修订。
2. 批量出片前，对全部目标影片 × 全部画幅先跑一遍不出片的版式检查（最长句、安全区、字号），问题一次修完再渲染。
3. 扩片逐项对照「已认可组合」，保存新旧对照图；「不重复确认」指不重复问作者，不等于不再对照。
4. 交付前把全部影片的开头和结尾排在一起横向检查，字标、片尾、音量和节奏一致。

宣传片系列的选材与画幅做法见[宣传片方法](promotion-film.md)和[多画幅与局部反馈](multi-aspect-revisions.md)，这里只列步骤和条件。

## 5. 检查和交付

| 项目 | 说明 |
|---|---|
| 输入 | 最终成片、时间源、制作单 |
| 产物 | `qa/summary.md` 与三张联系表、评审意见、最终验收记录、交付目录、交付报告 |
| 进入下一步的条件 | 响度达标；评审 P0 已修；[交付清单](../SKILL.md#交付清单)逐条有证据 |
| 不满足时 | 按缺陷所在层回到第 2–4 节；只修一轮后再复查，不无限循环 |

先连续复核实际版本的表达：开篇给了什么继续看的理由，后续是否有新的信息或感受，关键变化能否脱离解释文字成立，重复画面是否仍有推进，声音变化是否被画面承接。把疑点定位到时间和对象再修改；不靠自评分、切镜数量或固定高潮比例裁决审美，节奏类数字只作提醒。制作工具通过只证明技术项，不能替这层结论。

成片测量：`python3 scripts/qa_delivery.py final.mp4 --timeline timeline.json --platform 平台 --out qa/`。响度按 profile 的平台目标判定，不达标须先修；冻结段按时间线区分设计停留和待查；三张联系表交给下面的独立评审。

日常交付：实际输出完整解码、画幅／帧率／时长／音轨、资源与字体、最终播放。密集文字检查手机尺寸、最长句、切换点和播放器控制条安全区。新状态逻辑做顺序／逆序／冷启动取帧；局部修改检查接缝。已有有效证据不重复跑全量验证。

真实视听判断叙事、动作、音色、阅读窗口和同步。先试听实际最终混音中关键动作及其前后背景、对白的关系，再核对跨镜空间、自然度、动作同步、台词清晰度及瞬态是否刺耳。短音效即使峰值达标且已经入片，仍可能被背景掩盖；有可靠分轨时可检查同一动作窗口的短时电平辅助定位，不能把数字当成听觉判断，也不能将整混音电平误作音效电平。整片 LUFS、素材批准和接线通过均不能代替这一步。

在既有最终验收中记录上述结论及对应文件。HTML 工具会从原时间线生成最终文件的试听窗口，并拒绝缺少试听覆盖或仍待验的有声正式验收；其他装配器在原验收入口落实相同方法，不另建流程。没有真实试听就保留待验并可交付候选，不能由 Agent 根据技术结果自动填写通过。用户只认可音量时，保留该范围，不扩展成音色、自然度或整片认可。

复用未受影响的素材、音轨或历史结论，不等于把旧版正式批准移植到新文件。当前 HTML `check-review` 绑定最终文件、构建、渲染回执与试听计划，不支持按音轨相同自动继承整片批准；画面单独重编码也要刷新新文件回执，正式验收沿真实入口完成。可以注明旧音轨及原反馈未受影响，不能改 hash 或复制批准来冒充新版听审；没有新版实际试听时仍可交付候选。未变的最终文件和有效绑定则直接复用，不重复准备。

同一作品多版比较先明确是在比较整体创意还是某个变量，按 [版本比较](multi-aspect-revisions.md#版本比较与归因) 保留相应共同条件。必要的响度匹配试听不改原混音；没有真实观看／听审时交付候选，不从抽帧或指标补写认可。

### 独立评审

制作者看自己的片子容易看不出问题。成片测量后，按[独立评审](independent-review.md)请一个没参与制作的评审：宿主支持子 Agent 时开一个干净上下文的一次性评审，只给它三张联系表、制作单和测量摘要 `qa/summary.md`；不支持时制作者按同一清单自查，并标明「非独立」。评审先只凭画面复述这片讲什么，再列缺陷；不打分，不替代作者认可。P0 修完后最多再评一轮。

### 交付报告

交付时写一份简短报告，和成片放在同一交付目录：

- 成片路径与规格（画幅、帧率、时长、响度实测值）
- 检查结果：开头 3 秒、术语、响度、可读性提示各自如何处理
- 自主决定：照制作单原样列出
- 真实素材与示意内容的区分
- 最弱的一个镜头及原因
- 未验证项，例如「响度测过，未试听」
- 下一步会修什么

### 工程保留与清理

工程应能从依赖锁和可恢复素材重新运行，说明当前问题和下一步。保留 MP4、源工程、制作单、时间源、素材来源与许可证据、依赖锁和必要回执；修订中使用新输出名保留旧版本。用户授权清理后，收敛为一套可恢复工程与最终交付，删除被替代的渲染、重复打包及可再生缓存；先核对实际依赖和恢复入口，不删除仍被引用的素材或运行环境。保留清理范围与关键失败结论，不以清理抹掉验收边界。输入变化使相关旧回执失效。

已接受的本地交付可以用[发布交接](publish-handoff.md)导出中性发布包交给 `sansheng-distribute`，不重新渲染。对外分发前核许可证、署名和目标授权；本技能不会自动上传或发布，制作授权不自动包含对外发布或新服务付费。

## 6. 只保留能指导下一次的经验

沿现有工程记录或诊断保存必要发现，不新增独立经验数据库：适用题材、问题与具体观察、改动、对应源/媒体版本、证据和未验证范围。普通修字或临时网络失败无需提炼。

- 用户偏好保留原话与适用范围；不要将Agent自评、模拟批注或素材试听批准写成成片认可。
- 单片成功或失败先是观察。跨项目复现或可测量的事实才提升为通用做法，审美仍保留题材和用户范围。
- 获认可的混音、具体 gain／避让量及局部测量参考保存在项目层并绑定媒体版本；公共方法不将该修正量或局部阈值设成所有项目默认。
- 工具可以可靠识别的问题，优先修真实消费者并加入会失败的反例；不要只加一条提醒。
- 发现反例时修正或废止旧结论，保留被替换的依据。将成立做法归回对应reference，避免每次加载所有案例。

### 新规则准入

本 Skill 的规则只在下面三项都齐时才写入：

1. **触发事故**：哪条片子、哪个时间点、出了什么问题。
2. **可检查的判据**：怎样判断做到了没有。
3. **落点**：写进哪个阶段的哪个产物或工具。

能用工具查的，就改工具并加会失败的反例，不再加一段提醒文字。每条片子交付时最多提一条新规则，作者同意才写入。

本规则借鉴花叔的经验分层与回流。它约束证据与适用范围，不替Agent决定风格、镜头数量、节奏和所有声音。
