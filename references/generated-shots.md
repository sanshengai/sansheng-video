# 生成镜头与连续片段

需要提高人物光照、色彩、镜头观感或自然声音时，按 [生成片段的视听设计](generated-audiovisual.md) 把方向分别落实到场景首帧、表演请求和混音。产品方提供角色、教学、场景与验收约定；不要从参考片猜底层模型或一律改成同一种夕阳风格。

适用角色动作、剧情表演或生成视频，执行使用宿主已具备且获授权的入口，不另加导演。项目内容方提供角色、服装、声音、画幅与教学约束。模型能力以本次真实工具契约为准，不能混用客户端、原生 API 和其他平台的参数。

发请求前核对参考图／首末帧、画幅、时长、分辨率、音色和音频输入是否实际支持。新付费或上传私料仍受任务授权约束。profile 的 content_rules／legacy_root 可指向本机已有生成执行器及业务台账，按当前镜头读取，不加载全部历史。

## 对白与视频输入

角色对话需要稳定声线或精确口型时，先查本次实际入口能否接收既有对白音频、接受何种长度／格式及是否驱动口型；预设音色 ID 或文本台词不等于音轨输入。尚无契约或实测时保留未知，不靠提示词宣称支持。

- **已支持音频驱动**：确定对白音轨与实际轮次边界，再生成表演；需要多个机位时覆盖同一段已定对白，装配时引用相同音源与源区间。仍需核对口型、身份和表演，不因参数正确自动通过。
- **未支持或未证实**：沿已有原生音画入口生成，明确说话者、台词、声线与听者反应，再从实际媒体确定剪点。不能将后贴 TTS 当作已经驱动口型；只有另行完成适配和验证的入口才能采用前一路径。一次能力缺口不触发自动换供应商。

机位数量由内容决定，不要求为每句生成正反打或固定五个机位。多机位是可选覆盖；对白与听者反应的剪辑见 [视听设计](generated-audiovisual.md#对话与听者反应)。

身份／场景参考不等于固定构图。含人物的场景图再要求新角度时，模型可能把旧人物当背景、重造前景人物或复制道具；收片先核人数、位置、视线与道具。出现这类问题，优先保留成立的原生镜头，必要时在授权范围内用已成立的首帧局部重做。不要默认靠裁切近景遮住空间或表演错误；裁切不能修复关键动作、错误说话人或错误视线。

确有叙事需要才从同源画面裁近景，并检查源区域到交付画幅的放大比例、实际清晰度和相邻景别。输出尺寸仍是 720p／1080p，不代表裁后细节仍足够；在最终片连续观看切点，出现软化、人物突然变大或观看不适时撤回该处理。

## 镜头输入与验收

每镜输入写清：角色与人数、参考帧、景别、人物位置、主要动作、镜头运动、背景活动、说话人与台词、音色映射、环境声和结束状态。一个镜头围绕一个清楚的叙事变化组织动作，可以包含有先后关系的多人配合；动作负荷与实际时长相称，不机械限定为一人一个手势。走路写真实位移和起止位置，不能用“自然”替代观察指标。说话者和听话者的嘴部动作分清，不让系统补无关旁白。

连续镜头按意义切分，不按固定秒数强加转场。同机位可接尾帧；换机位先重新构图，避免把旧视角锁死。相邻镜头核对服装、道具、人物方位、动作阶段和声音桥。台词必须读得完，明确需要的结束留白；静帧只能定位疑点，最终看动态切点。

接尾帧或生成延续镜头时，同时保持主体大小、相机位置及运动方向／速度的合理接续；角色与场景参考一致，不代表机位已经连续。原生近景与宽景反复交替不适合当前内容时，应重新设计覆盖，而非仅在后期撤掉裁切或添加转场。

收片后实测时长／画幅／音轨，检查角色、手脚、口型、位移、脚滑、首尾连续性和最后台词。失败只针对可观察问题局部返工，优先改构图、动作负荷或时长；不无止境堆否定词或反复付费尝试。保留请求参数、模型与工具身份、参考资产、输出和失败原因，使用用户授权的预算与停止条件。

### 生成前核对实际动作

在原有分镜与场面调度阶段，先判断故事所需的行动能否从人物站位和道具布置中成立；交接路径、遮挡或同时发生的动作有问题，先改调度、构图或动作顺序，再做首帧，不等视频失败后补提示。一个叙事变化可以包含有顺序的多人配合，不机械限制动作数量。

发送前对着本镜真正使用的首帧，确认“现在是什么状态 → 发生什么变化 → 结束在哪里”：用可见特征和画面位置区分动作发起者、接收者及旁观者；交接物明确唯一数量、起初由谁拿、经哪里移动、最后由谁或什么表面支撑。整理织物等局部动作要区分接触的局部与固定的主体。核目的座位是否空着，以及完整台词与动作是否容得下。

把这次判断并入已有首帧／镜头审阅，只将必要的当前状态和动作终点编入最终提示。通读最终请求排除互相矛盾的动作，不以追加句子代替修正源头；不能逐镜粘贴整组最初的持物／座位说明。继承已批尾帧只证明来源，仍需判断下一步动作能否从这个姿态发生。对照实际发送的参考图顺序、说话人、声线、时长和提示，避免审核的是剧本，模型收到的却是另一个版本。工程有自动执行入口时，在原付费预留前校验这份审阅与实际输入，输入变化则重审受影响项；校验记录由工具派生，不再要求另一轮人工批准。记录与哈希核对不能替代画面判断。

### 每次返修反查流程

沿用项目既有故障诊断，保留原请求和媒体、缺陷时间码与处置结果，不为每次失败另开复盘表。把观察事实、已证实的流程缺口与待验证的因果推断分开：提示遗漏／冲突可从原请求查证；明确要求被违反不等于已经知道模型为何出错；新版成功也不能单独证明某个改动就是原因。证据不足时写明未知及最小核实办法。最终不重拍、转为剪辑解决的情况也保留原因。转写中的同音拼写或跨语言疑点，先用同一源媒体复核，不能为了匹配拼写反复生成；目标句提示的识别结果不算独立发音证据，静帧不算动态或听审。

确认确需再生成后，说明改变的变量、预期改善与如何验收，并检查尚未生成的同类镜头，再按既定预算局部执行。规则已写清但仍被违反时，优先降低动作负荷、改善可见关系或选择成立的镜头；补长提示不保证解决。固化的是能改变下一次决策的共性：在负责该问题的既有步骤修正规则，具体案例留项目诊断，不将全部历史灌入 Skill。能确定校验的输入关系接入原执行入口，并用应被拒绝的情形验证；需要看画面或听声音的判断仍保留真实审阅。不以追加额度代替复盘，也不作零返工承诺。

代码动画负责文字、图形、字幕和包装，不能替代已要求的人物表演。生成工具不可用时明确指出边界，不默默降为图片推拉或恢复被冻结的服务。生成片段检验后与其他媒体进入同一装配和交付流程。
