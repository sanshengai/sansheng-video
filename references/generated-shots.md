## 生成流水线：文件就是记忆

生成模型不记得上一条做过什么，连贯性靠 Agent 维护的文件、首帧闭环和关卡来保证，不能指望模型自己记住。

- **固定目录**：镜头表（唯一真源）、`参考图/`、`首帧/`、`请求/`、`回传/`（所有原始生成）、`选用/`（通过审片的片段）、生产日志。只有 `选用/` 里的片段进剪辑。参考图和首帧一旦用过就不再改名、不覆盖；新版本存成新文件，旧版本移到弃用子目录（防同名排序误用旧图）。
- **先锁资产与风格模块，再出首帧**：角色、场景、道具的参考图及主风格模块（光/色/质/构，见 [电影感与视听设计 §一](generated-audiovisual.md#一五个导演决定首帧吃前四层视频吃第五层)）经作者认可并标为锁定后，才进入批量出首帧。角色锁定前做一次压力测试：同一角色在不同景别、不同光线、与其他角色同框各出一张静图，长相与服装稳定才算锁定；年龄跨度大的人物按年龄段分版本锁定。
- **首帧静图走 `sansheng-image` `board` 闭环**：I2V 模式下 80% 的电影感由首帧决定。出首帧时明确告诉 `sansheng-image` 这是**视频分镜首帧（`board` / `storyboard-frame`）**，通过其 4 决定摄影编译器（或 `assemble_shot_requests.py --profile keyframe`）注入光影、色彩、质感与安全焦段，不绕过规则裸传一句 `natural light`。
- **出片前的关卡越靠前越便宜**：剧情因果与旁白对齐（只读文字）→ 首帧审阅（含光影质感、季节、人数）→ 三态核对（拿**实际首帧**重核动作，对不上只改动作，通常不必重出首帧）→ `lint_video_prompt.py` 跨字段机检 → 发送。
- **动态画风小样先于批量生成**：静图好看，动起来观感可能不同。新方向先连续生成同一段落 3–5 镜剪成 20–30 秒小样配临时音乐，经作者确认再放量。并行仅用于独立镜头；依赖前镜末态的镜头先解依赖。
- **视觉验收交给一次性子 Agent**：每镜按 ≤0.5 秒间隔或关键时间点抽帧拼图，子 Agent 对照镜头表逐镜核人数、造型、动作、机位和画风，只回传文字清单，判定写成「可用 / 取前 N 秒 / 重做」。主对话只看结论和少数关键图，图片不进入主对话历史。
- **生产日志**：每次生成记一行（镜号、请求版本、改了什么、结果、判定及任务编号）。

## 对白与视频输入

角色对话需要稳定声线或精确口型时，先查本次实际入口能否接收既有对白音频、接受何种长度／格式及是否驱动口型；预设音色 ID 或文本台词不等于音轨输入。尚无契约或实测时保留未知，不靠提示词宣称支持。

- **已支持音频驱动**：确定对白音轨与实际轮次边界，再生成表演；需要多个机位时覆盖同一段已定对白，装配时引用相同音源与源区间。仍需核对口型、身份和表演，不因参数正确自动通过。
- **未支持或未证实**：沿已有原生音画入口生成，明确说话者、台词、声线与听者反应，再从实际媒体确定剪点。不能将后贴 TTS 当作已经驱动口型；一次能力缺口不触发自动换供应商。

机位数量由内容决定，不要求为每句生成正反打或固定五个机位；对白与听者反应的剪辑见 [视听设计 · 对话与听者反应](generated-audiovisual.md#对话与听者反应)。

身份／场景参考不等于固定构图。含人物的场景图再要求新角度时，模型可能把旧人物当背景、重造前景人物或复制道具；收片先核人数、位置、视线与道具。场景参考图自带的季节、天气和时段往往压过文字设定，优先选与当场季节相符的参考；没有时写明保留布局与家具、只换窗外和植被，并在首帧审阅单列季节一项。

确有叙事需要才从同源画面裁近景，检查放大比例、实际清晰度与相邻景别；不能用裁切遮住空间错误、错误说话人或错误视线。

## 解说覆盖与真实连续时长

配音块的切分不自动构成画面剪点。连续场景跨句/跨语言讲解时继续消费源时间，禁止每个音频块都重置同一素材入点造成 1–2 秒动作反复播放。素材不足应补有意义的镜头、延伸连续动作或调整讲法，不能循环、倒放、冻结或减速撑时长。确需教学回看时记录明确目的与区间，并检查回看段内部仍自然推进。

原生声画的环境/现场声按实际场景连续入轨，讲解开始不意味着现场声全部关闭；旁白避让按真实语句与动作调整。

## 镜头输入与验收

连续镜头按意义切分，不按固定秒数强加转场。同机位可接尾帧；换机位先重新构图，避免把旧视角锁死。相邻镜头核对服装、道具、人物方位、动作阶段、光向和声音桥。接尾帧或延续镜头时，同时保持主体大小、相机位置及运动方向／速度的合理接续。

收片后实测时长／画幅／音轨，检查以下关键项：
- **连看前后接点**：动作有没有重新开始，人物与物件是否瞬移，光线、方向与景别是否跳变；查非预期字幕、Logo、水印。
- **最后台词实测**：取逐词时间，看最后一个词结束后离片尾还有多少余量（建议 ≥0.6 秒）；再测片尾 0.1–0.3 秒电平，仍在语音电平说明句尾被截断。
- **多人宽景口型**：缩略图看不清，须按每句时间段抽原尺寸帧放大每张脸核对嘴部开合；重试受限时优先拆成每镜一人说话或改用中近景。
- **动作抽帧 ≤0.5 秒**：1.5 秒抽一帧会漏掉“戴上”“掉落”这类短动作，误判为已发生或未发生。
- **声音先听再定去留**：原生音轨多为合轨，各镜自带音乐不等于全片连续；音轨检测与响度统计不能代替听审。

### 生成前核对实际动作

有旁白或解说的片子，出首帧之前先把每个镜头描述和它播放时的那句旁白对一遍：画面只表现已经讲到的事（防抢跑）。季节、时间、天气按段写进首帧提示；没有具名定妆的群众按集写一句统一造型。首帧画错以后，改运动提示救不回来。这一步只读文字，适合便宜模型批量跑。

在分镜与场面调度阶段，先判断行动能否从人物站位和道具布置中成立；交接路径、遮挡或同时动作有问题，先改调度与构图再出首帧。

发送前对着**本镜真正使用的首帧**，做三态核对（现在是什么状态 → 发生什么变化 → 结束在哪里）：用可见特征和画面位置区分发起者、接收者及旁观者；交接物明确唯一数量、起初由谁拿、经哪里移动、最后由谁或什么表面支撑；核对目的座位是否空着、完整台词与动作是否容得下。把判断并入最终提示，通读排除矛盾，对照实际发送的参考图顺序、说话人、声线与时长，避免审核的是剧本、发给模型的是另一个版本。

### 每次返修反查流程

按「实际文件 → 实际输入 → 任务意图」依次核对，区分素材生成缺陷、参考图冲突、请求转发遗漏、编辑错误和服务拒绝；按 [镜头请求契约 · 返修](shot-request-template.md#六返修先分型再决定重抽还是改) 走技术或审美双轨诊断。明确的安全或内容拒绝保留原始原因，可降动作负荷或改景别，不换近义词绕过；原因不明不猜具体触发点。把观察事实、已证实缺口与待验证推断分开。

确认再生成后说明改变的变量、预期改善与验收方式，同步检查尚未生成的同类镜头。规则已写清但仍被违反时，优先降动作负荷、改善可见关系或拆镜；不以追加额度代替复盘，也不作零返工承诺。

### 按类别统计，规则回写到对应层

系列或批量生产每做完一批（如 10 集），把审片结论按固定类别汇总：形象、动作与场景突变、抢跑、文字乱码、时代穿帮、合规、表现不足、审美平淡。占比最高或上升的类别回到所属层修：锁层（风格模块、角色锚点、故障锁）、首帧层（`sansheng-image` 摄影配方）、单镜层（动作与运镜写法）、适配卡（入口行为）、核对关卡（首帧审阅、三态核对、`lint_video_prompt.py`）。改完拿旧批回测确认能拦住已知问题，再用于下一批。

代码动画负责文字、图形、字幕和包装，不能替代已要求的人物表演。生成工具不可用时明确指出边界，不默默降为图片推拉或恢复已冻结服务。生成片段检验后与其他媒体进入同一装配和交付流程。
