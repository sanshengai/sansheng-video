# 独立评审

制作者看自己的片子，容易用「我知道这里想表达什么」补上画面没给出的信息。独立评审只看观众能看到的东西，先说出这片讲什么，再找缺陷。它不打分，也不替代作者认可。

## 什么时候做

成片测量（`qa_delivery.py`）之后、交付之前做一次。P0 修完后最多再评一轮，不无限循环。局部修改只评受影响的范围。

## 谁来做

- 宿主支持子 Agent 时，开一个干净上下文的一次性评审，只给它下面列的输入，不给制作过程、对话记录或制作者的自评。用完即止，不留着复用。
- 宿主不支持时，制作者按同一清单自查，并在评审意见开头写「非独立」。

## 输入

| 输入 | 来源 | 用途 |
|---|---|---|
| 0–3 秒联系表 | `qa/hook_sheet.jpg` | 静音刷到时，前 3 秒能否看出这片讲什么 |
| 手机尺寸联系表 | `qa/phone_sheet.jpg` | 手机上字是否看得清、是否压到平台界面 |
| 节拍联系表 | `qa/beats_sheet.jpg` | 每段画面是否推进、有没有重复或空转 |
| 制作单 | `brief.md` | 比对主张、术语和段落表 |
| 测量摘要 | `qa/summary.md` | 响度、待查的冻结段、切点 |

缺哪一项，评审意见里对应部分写「无法核对：缺 X」，不猜。

## 步骤

1. **先复述**：不看制作单，只凭三张联系表写一句「这片讲的是……」。再只看 0–3 秒联系表写一句「前 3 秒观众知道的是……」。
2. **比对**：打开制作单，把两句复述与「一句话主张」「开头 3 秒」比较，写明一致、部分一致还是不一致。
3. **列缺陷**：每条写时间点、现象、可能原因、可以测量的修法。分级：
   - **P0**：观众会误解主张；事实或数字错误；关键文字看不清或被遮挡；响度不达标；时间线声明有声而成片缺音轨；录屏露出账号、通知、令牌等敏感信息。
   - **P1**：竖屏信息流片子的前 3 秒说不清（已写豁免的除外）；某段文字读不完；术语没出现；画面连续几段没有新信息。
   - **P2**：表面细节，例如对齐、间距、色彩小偏差。
4. **最弱镜头**：指出一个最弱的镜头和原因。
5. **结论**：「可交付」或「再修一轮」。有 P0 就是「再修一轮」；P1 由制作者修好，或在交付报告里写明不修的理由。

不打分，不写「整体不错」之类的评价，不提风格偏好。节奏类数字（新信息间隔、高潮位置）只作参考，不作为缺陷依据。

## 评审意见格式

```markdown
# 评审意见（独立｜非独立）

复述：这片讲的是……
前 3 秒：观众知道的是……
与制作单比对：一致／部分一致／不一致，差在……

| 级别 | 时间 | 现象 | 可能原因 | 修法（可测） |
|---|---|---|---|---|

最弱镜头：……，因为……
无法核对：……（没有就写「无」）
结论：可交付／再修一轮
```

## 给子 Agent 的简报

派发时把下面这段连同五个文件的绝对路径一起交给评审，不附其他内容：

> 你是这条视频的独立评审，没有参与制作。按 `references/independent-review.md` 的步骤和格式工作：先只看三张联系表复述这片讲什么、前 3 秒观众知道什么，再打开制作单比对，然后按 P0／P1／P2 列缺陷，指出最弱镜头，给出「可交付」或「再修一轮」。不打分，不评风格偏好；缺少的输入写「无法核对」，不猜。只读，不修改任何文件。最终回复就是评审意见本身。
