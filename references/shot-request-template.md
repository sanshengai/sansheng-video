# 镜头请求契约：发给视频生成器的固定结构

用于逐镜生成的视频（Muse、Seedance、Kling、Veo、Sora、Grok 等任何入口）：一条约 4～15 秒的镜头请求由哪几层数据组成、首帧与视频如何分工、按什么顺序写、各入口在哪里允许不同。整条流程见 [生成镜头](generated-shots.md)；摄影语法、风格模块与审美诊断见 [电影感与视听设计](generated-audiovisual.md)；Muse 入口实测见 [Muse 交接](muse-handoff.md)。

核心原则：
1. **镜头请求是控制文件，不是创作散文；分镜台账（IR）与发给模型的编译提示词必须拆开**。台账给导演和剪辑留完整信息（含 `STYLE / WORLD / CUTS TO / 完整人物档案`），编译输出层按目标入口与镜头类型裁掉冗余。
2. **首帧（T2I）与视频（I2V）职责硬切分（Delta 原则）**：80% 的电影感（光影方向/光比、色彩、胶片与空气质感、构图与焦段）在**首帧静图阶段**锁死（通过 `sansheng-image` 的 `board` 场景或 `--profile keyframe` 编译）；I2V 视频提示词**绝不重复描写首帧里已锁定的静态建筑与外貌**，并**删掉静止构图层换成运镜**，只写时间轴上的 **Delta（运镜 + 单主动作 + 物理微动 + 光影/身份保持 + 声音）**。
3. **前置权重（Front-Loading）与注意力预算**：主流扩散视频模型对提示词前 30% 注意力最高——I2V 将 `Ref Lock + Camera + 主动作` 置顶、Guard 置底；预算控制在活照片 65–95 词、单动作／连续运动 85–120 词。

## 零、生成前先分流（五选一）

不是所有动态镜头都该送扩散视频模型：

| 类别 | 适用场景 | 路由与 `profile` | 关键原因 |
|---|---|---|---|
| **0. 确定性静图动效** | 地图路线、竹简/碑刻/手稿展示、文字卡片、局部光晕/飘尘 | 本地 HyperFrames / FFmpeg 缓推 / `sansheng-image`（`sb.py motion` / `animate wake`） | 零伪汉字、零透视漂移、不烧生成额度 |
| **1. 首帧静图编译（Keyframe）** | I2V 之前的每镜首帧出图 | `sansheng-image` `board`（`storyboard-frame`）或 `assemble_shot_requests.py --profile keyframe` | 把光影、色彩、质感、构图与安全焦段锁进第 1 帧，不让视频模型临场猜 |
| **2. I2V 活照片（Still）** | 人物保持姿势、帝王群臣、室内静态密谈、纯慢推/固定展示 | `--profile muse-i2v-still` | 人物与构图锁死不动，只放开 2–3 样环境微动白名单，防模型自己加转身或路人 |
| **3. I2V 连续平稳运动（推荐默认）** | 多数叙事镜头与航拍：第 1 帧起持续 7 秒可见、匀缓运动 | `--profile muse-i2v-continuous` | **实测优选**：消除“第 4 秒后僵停”的呆滞感，构图随单向运镜自然变化，光线与场景恒定 |
| **4. I2V 停稳单动作（Action）** | 需要前段做完动作、后段完全定格给剪辑硬切或叠加文字的镜头 | `--profile muse-i2v-action` | 提前到 `0–4s` 完成主动作，`4–10s` 保持第 4 秒终态构图 |
| **5. T2V / 多参考有声** | 无首帧情境再现（`muse-t2v`）；多参考角色对白（`grok-r2v` 等） | `--profile muse-t2v` / `--profile grok-r2v` | T2V 保留 `STYLE(去构图) + WORLD`；`grok-r2v` 禁用 `slow` 词，对白后留约 1 秒自然表情余量 |

## 一、三层数据拼成一条请求

| 层 | 内容 | 来源 | 什么时候变 |
|---|---|---|---|
| 全片锁 | **结构化风格模块**（`anchor / light / color / texture / composition / mood / motion`，兼容旧单句）；角色锚点（固定名字 + 外貌句）；画幅与输出项；声音政策；高频故障锁 | 作者认可、标为锁定的资产表 | 全片不变，逐字复用（回忆/梦境切第 2 风格） |
| 段落锁 | 场景锚点：地点、时代、季节、天气、主光；本段环境声底 | 分镜 | 同一段内不变 |
| 单镜 | 起始状态、一个主动作（物理因果）、一种运镜和节奏、末态、动作声、人声 | 镜头表 | 每镜不同 |
| 入口适配 | 字段标签与语言、锁怎么传、参考图怎么给、取用时长、禁用词、声音能力 | [入口适配卡](#四入口适配卡) | 换入口或入口行为变化时 |

请求由脚本从前三层机械拼出，再按适配卡渲染，不手写整段。结构化风格锁下：**首帧编译器取 `anchor + light + color + texture + composition + mood`**；**视频编译器自动剥离 `composition` 静止构图层，只保留光色质感保持与运镜**。

**两层文本**：发出去的东西分「项目说明」和「镜头请求」。剪辑、转场、调色和配乐由后期负责，不要求生成器做。项目说明能不能只发一次，取决于入口（见第四节「锁怎么传」）。

## 二、台账 IR 字段与顺序

| 顺序 | 字段 | 写什么 | 为什么在这里 |
|---|---|---|---|
| 1 | `CAST` | `EXACTLY N CHARACTERS, NO DUPLICATES: 名字…. No other people.`；空镜写 `NO PEOPLE IN FRAME` | 人数锁放在最前，防止角色被复制、凭空多出路人 |
| 2 | `REFERENCES` | `image 1 = 用途; image 2 = 用途`，顺序与附件一致；身份参考写明「只取长相和服装，不继承背景、构图和画法」 | 每张图只承担一种用途（第三节） |
| 3 | `STYLE` | 全片风格模块（优先结构化 5 层），逐字复用 | 风格一换措辞，画风就会漂移 |
| 4 | `CHARACTER <名字>` | 每个出镜角色一句锚点：年龄感、脸型与须发、发型与颜色、2 个以上不可混淆的服装或饰物。I2V 中近景改用 12–18 词短锚点，大远景/背影省略 | 首帧与视频用同一视觉锚点，图文才不打架 |
| 5 | `WORLD` | 本段场景锚点：地形、季节、天气、主光方向。只写环境，不写某个揭示镜头才出现的物件 | 写进场景锚点的物件，每一镜都可能提前出现 |
| 6 | `FORMAT` | 画幅、单一连续镜头、画面无文字、无 Logo、无水印；项目登记的高频故障锁 | 固定的输出项 |
| 7 | `FIRST FRAME (0s)` | **附了首帧图**：写「从首帧原样续演：姿势、位置和道具状态保持」，只补图上看不出来的；**没附首帧**：景别、机位、焦段与站位 | 图文矛盾时模型二选一，常常换场景 |
| 8 | `ACTION` | 全镜一个主要动作，写明物理因果与可见变化（连续运动按 `0–7s` 匀缓展开；停稳动作按 `0–4s` 完成 + `4–10s` 保持） | 一镜一个动作，避免复杂拼接 |
| 9 | `CAMERA` | 一种运镜路径 + 节奏（全程匀速或停止点）；固定机位写 `Locked-off tripod <景别>. The camera remains still. No push, no zoom.` | 防止镜头自行推近、甩镜或漂移 |
| 10 | `LIGHT` | 本镜的光向、光比和色温；I2V 无单独变化时写「与首帧一致，从头到尾不变」 | 后半段最常漂的就是天气和光 |
| 11 | `AMBIENT MOTION` | 两种以上与物理环境呼应的微动（风、火光摇曳、尘埃、水光、衣袂、飘雪） | 画面要“活”，靠环境层的持续微动 |
| 12 | `END STATE` | 人物位置、朝向、道具在谁手里，再重复一遍人数 | 供下一镜衔接，也是对人数的第二道锁 |
| 13 | `CUTS TO`（仅留台账） | 下一镜从什么状态开始，靠什么衔接（绝不编入模型提示词） | 避免视频模型在 6 秒左右提前切场景 |
| 14 | `AUDIO` | 1 个确定环境底噪 + 至多 1 个与可见动作绑定的拟音 + `Music: none` + 明确人声策略 | 声音越杂，后期越难和环境声底、配乐对齐 |
| 15 | `CONTINUITY` | 保持参考图里的角色造型、服装和颜色 | 收尾再强调一次 |

## 三、写法规则（防穿帮 + 电影感）

- **用可执行摄影词，删空泛形容词**：不写 `cinematic / photorealistic / high quality / natural light` 敷衍了事；光影、色彩、质感、焦段写法见 [电影感与视听设计 §一](generated-audiovisual.md#一五个导演决定首帧吃前四层视频吃第五层)。
- **用正向写法**：写想要的画面，不写长篇禁止清单。「不要」只用在三类地方：输出项（字幕、Logo、水印、音乐、对白）、人数与机位锁、项目实测登记的高频故障锁（如文字载体空白、兵器不指人）。
- **物理因果与声画因果**：写力源如何推动结果（“急风掠过油灯，火苗斜向右侧，墙上人影轻晃”），好过抽象结果（“火光闪烁”）；声音推动画面时写在同一句（“门闩咔嗒一响，他抬眼看向门口”）。
- **情绪写成可见微动作 + 情绪克制**：写“低头、手指收紧、喉结轻动、眼神移开”，不写“她很难过”；**悲伤／凝视特写显式写“固定机位，身体不动，仅眼神缓慢变化”**，防模型让人物乱哭乱晃。
- **一镜一个动作、避开状态切换**：起身、坐下、跪下、转身、倒地、大幅转头、开合门盒失败率最高，优先拍它的结果或改用镜头运动；连续过程拆成两镜。
- **多主体只让一组动**：帝王加群臣、两军对阵、人群聚会，先写最显眼的人在哪，再让“一人动、其他人看”或“人物保姿、仅镜头慢推 + 旗烟火水微动”。
- **视频删静止构图**：动态运镜（`dolly-in / push-in / track / glide`）下，不要在 `Ref Lock` 里同时写死 `keep exact composition / frame edges identical`，改为 `keep scene, subjects and lighting consistent`，让构图随运镜自然演进。
- **一个角色一个名字、参考图按用途声明**：全片固定一个大写名字；身份参考只管长相服装，场景参考只管空间与光，本镜首帧管 0 秒起点。
- **音画联合防声源污染**：无对白镜头**严禁**出现 `choose from:` 多选题或 `gasp / sigh / cheer / chant / speaking / orders` 等人声诱发词；只写「1 个确定环境声 + 至多 1 个动作声 + `no music, no speech, no human vocalizations`」。有对白镜头标清谁先谁后，未说话者显式写“嘴巴闭着在听”。
- **室内镜禁提户外/村舍否定词**：没有独立 `negative_prompt` 参数的模型会把 `no villages or huts` 正向激活（粉红大象效应）；室内镜 `Guard` 只留室内真会翻车的 1–3 条。
- **全片用同一种语言写请求**：给编排者的说明可以用中文；同一系列内模型提示词保持单一语言。

## 四、入口适配卡与主流模型范式

契约规定「写什么、按什么顺序」；每个生成入口用一张适配卡声明八项实测事实（投递方式、锁怎么传、参考图、取用时长、运镜与用词、声音、批量与额度、失败信号），渲染脚本按卡输出。未核实的写「未知」，不照别的入口推断。

| 模型范式 | 代表入口 | 写法核心差异 |
|---|---|---|
| **单图 I2V + 对话代理** | **Muse 网页**（卡：[Muse 交接](muse-handoff.md#适配卡)） | 经对话代理，必须逐镜完整携带精简规则（65–120 词）；只传 1 张本镜首帧图；10 秒取前 6–7 秒；支持连续 7 秒平稳运动或活照片慢推 |
| **多参考 + 单段多镜** | **Seedance 2.5 / Kling 3.0 / MiniMax H3**（按需补卡） | 支持多图/视频/音频参考，开头显式编号 `@image1` 分工；**单段内切镜必须写明 `切 + 景别`**（禁写“转到/来到”防模型做成连镜摇移）；I2V 不重复描写已入图元素 |
| **物理模拟与光学敏感** | **Veo 3.1 / Sora 2 / Luma Ray 2 / Wan 2.2**（按需补卡） | 对摄影机/焦段/色温专业词（`50mm f/2.0, 3200K key`）和物理力源因果高度敏感；用明确时间拍点（`0–2s / 2–6s`）控节奏；Veo 前置权重明显，先写景别与主体 |
| **直连多参考有声对话** | **Grok 等直连 R2V**（由使用项目维护适配卡） | 可多参考带对白与声线；实测禁用 `slow` 类运动暗示，改写正常速度具体动作，对白末尾留 ~1s 自然表情余量 |

## 五、发送前自查

逐镜过一遍下面的问题；完整的三态核对方法见 [生成镜头 · 生成前核对实际动作](generated-shots.md#生成前核对实际动作)。

- 首帧本身的光影、色彩、质感、焦段是否已达标？（首帧发平，视频救不回来）
- 动作能否从**实际首帧**里人物现在的姿势自然接着演？有无状态切换或多人同时各动各的？
- 运动镜里是否已去掉“保持构图不变”冲突句？特写是否避开了超广角？
- 道具在用之前是否已在场？力从哪里来？`CAST` 与 `END STATE` 人数一致吗？
- 无对白镜是否已清干净人声诱发词与 `choose from:`？`CUTS TO` 是否已剥离出模型文本？

## 六、返修：先分型，再决定重抽还是改

先区分**“技术故障”**还是**“审美平庸”**，双轨对症处理，不靠无止境堆否定词硬抽：

| 轨道 | 失败类型 | 怎么认 | 怎么办 |
|---|---|---|---|
| **技术轨道** | 随机质量缺陷 | 同一请求有时对有时错：手指、口型、局部变形 | 原样重抽，按适配卡上限（如最多 2 次） |
| **技术轨道** | 拒绝或不按首帧 | 入口拒生成，或第 0 秒与首帧相似度极低 | **改一个变量，不只改措辞**：退回 `still` 活照片 + 平稳慢推；正面人脸近景屡被拦时换景别/侧面/背影首帧，最后才用本地缓推替代 |
| **技术轨道** | 结构性故障 | 每次都在同一处出错：场景突变、换脸、道具消失 | 回源头改首帧、降动作负荷或拆成两镜，不在单镜末尾追加否定句 |
| **审美轨道** | 画面太 AI / 平淡 / 脏色 / 乱动 | 技术没穿帮，但缺乏电影感或情绪不对 | 按 [审美出片诊断表](generated-audiovisual.md#三审美出片诊断表按删层塌陷序排查) 的顺序排查 **光影 → 质感 → 色彩 → 构图 → 运动**，一次只改 1–2 层 |

- 一次只诊断一个故障，最多改 5 行，旧版本全部保留以便并排对比。
- 同一故障反复出现按顺序加码：普通描述 → 精确数量/位置/方向 → 大写归属或数量锁 → 拆镜。
- 一镜试了 10～15 次（或达入口返修上限）仍不收敛，立刻简化动作、换景别或拆两镜，不再改措辞。
- 每次生成在生产日志追加一行：`| 镜号 | 请求版本 | 改了什么 | 结果 | 判定 |`。

## 七、用镜头表批量拼请求与跨字段矛盾机检

整片镜头写成一张 JSON 镜头表，用 `assemble_shot_requests.py` 按入口编译并运行 `lint_video_prompt.py` 拦截矛盾（光影昼夜冲突、静机配运镜或出画远去、室内词混入村舍、禁声镜混入人声诱因、无字锁配读卷写字、`choose from` 菜单音效、`CUTS TO` 泄漏、词数超预算，以及摄影级警告：空泛风格词缺光学要素、特写配超广角、运动镜混入静止构图锁）：

```sh
# 1. 编译首帧静图提示词（吃结构化 4 决定：光/色/质/构）
python3 scripts/assemble_shot_requests.py <镜头表> --profile keyframe --lint --out <首帧提示目录>
# 2. 编译 I2V 连续运动视频请求（自动剥离静止构图与冗余世界观）
python3 scripts/assemble_shot_requests.py <镜头表> --profile muse-i2v-continuous --lint --out <视频提示目录>
# 3. 单独校验已有提示词或镜头表
python3 scripts/lint_video_prompt.py <镜头表或文本> --mode i2v-continuous
```

可用 `--profile`：`keyframe`、`muse-i2v-continuous`、`muse-i2v-still`、`muse-i2v-action`、`muse-t2v`、`grok-r2v`、`legacy`（默认，兼容旧 15 段全量台账）。

**结构化 `locks.style` 示例**（兼容旧字符串）：
```json
"style": {
  "default": {
    "anchor": "Live-action Oriental historical cinema",
    "light": "Directional late-afternoon side sunlight through wooden lattice, natural shadow falloff",
    "color": "Restrained low-saturation earth, indigo and warm timber tones (max 3 dominant hues)",
    "texture": "Subtle 35mm film grain, light airborne dust motes, authentic linen and timber wear",
    "composition": "35mm medium framing with timber pillar foreground frame, natural depth of field",
    "mood": "Calm, grounded historical presence"
  }
}
```
编译 `--profile keyframe` 时自动拼入全部 6 项；编译 `--profile muse-t2v` / `--profile muse-i2v-*` 时自动剔除静止 `composition`，避免与运镜冲突。
