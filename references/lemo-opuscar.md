# Lemo-Opuscar：风格语法与实现参考

结论：值得融入，放在**新作定视觉方向**和**具体镜头遇到实现难点**两个位置。不是每次做片先刷样片。日常默认沿当前项目的生产入口；用户明确要比较原版时，可在隔离的项目目录临时加载固定版本插件，记录实际调用和引擎，不改全局入口。

来源：[作者原文](https://x.com/lemomo_ai/status/2103823847632060854)、[新帖](https://x.com/lemomo_ai/status/2113195080517562646)、[仓库](https://github.com/lemomo-ai/lemo-opuscar)、[在线图鉴](https://lemomo-ai.github.io/lemo-opuscar/)。当前取回与引用统一固定 `3961ddb3d24d8876e0e2754f7790d66908acee51`，权威 `styleboard/catalog.json` 为 **59 种**，排除 `_template`；另有 **OPUSCAR 98 的 98 条电影风格语法**，不是98套可执行工程。

本轮在保留旧51项研究的基础上，新增8项 STYLE 源码阅读，并迁移旧引用：92个已绑定文件变化，75处引用按相同行内容定位，23处人工核对翻译注释或修订链接。该结论不等于已观看最新59支片；旧版抽帧研究只属于当时的51支。新目录索引包含1688个文本／代码／配置文件，每个文件同时经过上游git blob及SHA256核验。

## 看完仓库后的判断

全树清点 2497 项、2091 个文件约 110MB；研究缓存取得 1576 个文本／代码／配置文件，核对全部 51 种 STYLE／DEMO 的结构和分类，并重点追踪导演、技术、核心渲染／配音／采样／校稿及相关样片实现。后续逐项建立51张用途/机制卡，深读12种关键实现，并对6支官方成片做时序抽帧研究。未逐个运行51支片，时序抽帧也不是连续观看或听审；不能把作者展示质量当我们已复现的质量。

| 部分 | 实际价值 | 如何采用 |
|---|---|---|
| DIRECTOR.md | 对标学语法、内容自己的开头结尾、风格内部转场、预备动作与跟随动作、看关键动作 | 转为镜头设计判断，不再启动一轮导演采访 |
| TECHNIQUE.md / core | 确定性 render(t)、单时间源、真实配音时长、语音回听、接触表、混音 | 与现有机制合并；默认仍用 HyperFrames 和本项目声音工具 |
| 59 个 STYLE.md | 材质、配色语义、字体、动作、镜头及声响构成完整语法 | 一次选一个主风格，按题材查不超过 3 个候选 |
| DEMO.md + demo/ | 笔刷、关节、纸张、摄影机和 shader 有实际实现，远胜仅列提示词 | 先写自己的镜头目的，再取选中风格代码，抽一个机制进项目 |
| 实证影像 8 种 | 卫星、点云、白模、数据实物、CAD 拆解、显微、档案等，把真实材料变得可解释 | 有对应事实材料才用；另列事实证据，不把示范片数字挪来用 |
| OPUSCAR 98 | 77 条 2D、4 条 2.5D、17 条 3D 的画面提示与镜头导演拆解 | 用户要电影感或片头时再搜；只借语法，不带入电影人物、标志和情节 |
| 乐器 sampler / pluck | 真采样原创配乐、按事件写谱、自动署名有价值 | 需要原创配乐再专项采用，不默认下载约 1.4GB 全套采样 |
| plugin 安装器与发布工具 | 为其独立仓生产与图鉴维护服务 | 日常不自动装；明确原版实验仅项目级临时加载，先核 setup 行为，不自动更新或改共享仓 sparse-checkout |

这和“找一个类似视频照着改”有区别：先按自己的事实和内容确定要表达的变化，STYLE 用来约束视觉语法，DEMO 用来学实现。仅换示范片文字会继承别人的结构与节奏，容易出现形式很好看、内容讲不清。

原帖建议其他模型先从能跑的样片改起；当前仓库进一步强调先有自己的 treatment 再读 DEMO。两者可兼容：复用可运行的绘制引擎，自己写内容、镜头和时间线。新效果先做一个真实镜头验证，再扩成全片。

## 对我们最有用的几组

- 教学／解释：`whiteboard` 白板、`blueprint` 工程图、`iso-infographic` 等距信息图、`dataviz` 数据叙事。它们让对象和关系逐步出现；沿已有教学栏目品牌和角色规则，不整片改成别人的外壳。
- 成人书籍、人物与企业：`urban-sketch` 钢笔淡彩、`halftone-dossier` 案卷、`archive-lighttable` 档案灯台。需要真实史料的镜头先找有来源的资料，不以“档案风”伪造史料。
- 产品与功能：`living-screencast`、`dark-keynote`、`swiss-motion`，借界面关注点、空间和排版节奏；演示真实产品时核对真实功能，不把重画界面冒称实机。
- 情绪与文化短片：水墨、油画、纸雕等按故事选择。角色动画与 3D 的实现成本更高，先验证关键动作与材质，不因风格库里有就承诺一键复现。

## 快速搜索与取回

```sh
python3 scripts/lemo_reference.py search '讲清关系，逐步理解'
python3 scripts/lemo_reference.py search '产品宣传，真实操作和结果'
python3 scripts/lemo_reference.py inspect living-screencast
python3 scripts/lemo_reference.py search 'data science'
python3 scripts/lemo_reference.py search '工笔' --cinema
python3 scripts/lemo_reference.py get whiteboard --out PROJECT/reference-whiteboard
# 已写自己的内容和镜头后，需要查实现才取 demo 源码：
python3 scripts/lemo_reference.py get whiteboard --demo --out PROJECT/reference-whiteboard-code
```

检索在捆绑索引里本地完成，每次最多3项。先按中文用途、表达机制或别名匹配；找不到时回退原目录关键词，不要求先知道风格名。结果给出适合用途、机制和实际需要；`inspect`再看画面/声音、边界及上游路径与行号。索引只是候选，不能代替理解本项目。明确的“不要…／避免…”独立短句可排除该短句关键词；它不是通用自然语言否定解析器，复杂约束仍由Agent判断。`get` 默认只取 STYLE；`--demo` 取该风格的说明和文本源码，不取成片、字体二进制、声音、全库模型或采样。固定 revision 和逐文件 SHA256 校验，按版本缓存，拒绝覆盖目录；回执保留来源、版本、文件和署名。它不会执行下载的 build.sh。样片引用的 core 模块、字体和媒体需要按所选机制逐项处理，取回代码不等于已能一键重建样片。

实测 `whiteboard --demo` 取回 23 个文本源码、352797 字节，包含真笔触的 `engine/wb.js`。其核心以弧长和时间窗口驱动笔迹，笔尖缓入缓出，积墨与干擦纹理分层，摄影机统一世界坐标；适合抽取为解释关系的单镜头。笔触纹理和相机可分别复用，不必连同 GPS 故事、配音和乐器重建。

## 从风格名称深入到表达机制

先分清所选条目提供什么：风格说明只能指导方向，机制源码解决局部动作，示范工程可能缺媒体／字体／core 依赖；只有确认输入、依赖、许可及实际替换运行后，才能称为本项目可用的模板。当前 `get --demo` 取文本源码，不提供已装配的商业模板，也不保证原片一键重建。

采用理由回到本片缺口：要借哪项可见变化、需要什么素材和声音、用当前引擎能否实现。按 [主流程的连续短样](production.md#4-制作与修订) 验证选中机制，不能以读过 STYLE 或展示静帧代替。无匹配候选时可以原创，但仍需验证关键交接；不因首次泛词检索偏题而换遍全库，也不把示范作者的完成度当作当前工程能力。

59种风格不是59个可随意更换的皮肤，也不是59支保证可一键复现的模板。每项同时包含：适合讲什么、靠什么变化表达、画面与声音怎样相互作用、需要哪些真实材料/实现能力、哪里不适用。按当前缺口取一两项机制；整套采用也应有本项目自己的内容与工程依据。

| 本项目的问题 | 已追踪的上游机制 | 使用前提与边界 |
|---|---|---|
| 功能宣传只有成果轮播 | `living-screencast` 用语义锚点把操作、界面状态和动作声联在一起 | 有真实功能与界面依据；无需照搬吉祥物、甩镜或章节密度 |
| 同一内容换结构后关系难懂 | `whiteboard` 在一张可返回的关系图里逐步书写和组织 | 让对象身份与关系保留；示例词窗是估时，不能借来宣称逐词音频对齐 |
| 比较先说结论、证据看不清 | `archive-lighttable` 的固定比较空间、尺规和材料显现 | 真实材料和比较条件有来源；档案材质不是事实真实性 |
| 跨场景只能硬切或突然放大 | `paper-popup` 的翻页阶段、纸体与外部光，以及 `one-line` 的连续笔迹 | 用本项目对象重写交接；纸页/线条不能自动保证连续观看舒适 |
| 数据片与声音各做各的 | `dataviz` 数据事件同时给出画面与声响 | 数据事实和音色映射分开验证；不用声音包装不成立的数字 |
| 艺术片材质只是装饰 | `impasto` 将颜色、笔触和物件变化写进剧情，`urban-sketch` 用共同路径关联颜色/速度/声像 | 保留自己的故事；文档写“静音”时还须检查实现是否仍有音床 |
| 拆解后找不回整体 | `teardown` 的总—分—合、部件空间秩序及运动/接触错位安排 | 有真实结构依据，不能把示例CAD及尺寸挪作项目事实 |

声音不只来自音乐文件：笔触、纸页、输入、接触或材质变化可由同一事件导出。先核已有原声和精选库；需要算法声音或原创配乐时再核工具、许可与真实输出。不要因示例有完整音频引擎，就在所有项目复制整套采样器。

先独立写自己的方案，再读DEMO是为了保留自己的推导；借鉴后应能指出“哪项变化帮助讲清了内容”。同主题的两种风格可以各有优点，无需统一成一种审美；风格的长处不自动成为别的题材的硬规则。

看示范片也要复核机制描述。`silent-film` 是无对白动作叙事，允许文字间卡；`swiss-motion` 不只建立网格规则，片尾还比较有目的的破例；`glass-product` 展示材质与形态，并不因此证明产品功能。`one-line` 的局部意义依赖最后的整体揭示，不宜未经重写就拿来逐步推导概念。把这些条件写进选用理由，避免风格名把创作可能性缩窄，或让漂亮形式代替内容证据。

检查转换时先确认对象归属和叙事相位：旧数字可能留作比较，文字可能正在写入，短暂遮挡可能承担转场。定位前后状态和阅读窗口后再判断，不能凭一帧判错误；同样，精美场景不能代替关键人物、表情或说明文字的可见性。时序抽帧可定位疑点，不能代替连续观看或直接听审。

## 与现有生产流的关系

内容稿 → 必要时查 Lemo 定一套风格／实现 → 自己的镜头设计 → 需要具体运动才查 Motion Prompt → 新旁白按 TTS 实际音频定时 → 缺真实通用画面查 Pexels → 有声音目的按[资源配置](assets-and-profile.md)查项目与显式精选库，缺件再查 Openverse → 全部接原时间线、素材锁、渲染与混音 → 视听验收。

讲解片以真实旁白与理解窗口为先；音乐驱动短片才先定音乐网格。不要无条件采用上游“至少四种运镜”“每个动作有音效”“至少两次静音”“三套故事结构”等数量要求。已有工程局部改字、换声音、换图不触发风格重选。用户已选方向不加两次确认，不把上游 AGENTS.md 当本项目规则。

## 更新引用库：候选 → 校验 → 采用 → 项目验证

1. 保留当前索引与来源清单（Git历史或研究目录），固定上游40位commit并取该快照。不要用浮动main作为项目引用版本。
2. 以 `styleboard/catalog.json` 决定范围；新增风格阅读STYLE与必要DEMO，写用途／机制／画面／声音／前提／边界及真实行号。旧引用按旧文件与新文件对照迁移；文件变化不能只改hash或假定原行号仍成立。自动相同行映射只是辅助，替换段需人工阅读。研究、抽帧、连续观看、听审和复现分别记录。
3. 生成独立候选目录，不覆盖正式库：

```sh
python3 scripts/lemo_catalog.py --source SNAPSHOT --revision COMMIT40 --cards REVIEWED-CARDS.json --out NEW-CANDIDATE
```

工具从GitHub取得固定commit的完整git树，核验目录、电影语法、LICENSE、README及所有选中的文本git blob；拒绝空目录、缺卡、重复、越界引用、源文件改动、已有候选目录。输出四份索引／许可与 `review.json`，列出增删、文件变化和来源清单指纹。候选只证明引用与源码一致，不能自动理解修改或判定画面质量。
4. 阅读差异和许可段后，显式复制候选 `catalog.json`、`creative-index.json`、`creative-sources.json`、`LICENSE` 到 `scripts/vendor/lemo-opuscar/`，把 `lemo_creative.py` 的 `SOURCES_SHA256` 更新为报告值；保持运行时完整覆盖、hash与行范围的拒绝能力。更新这里的版本、数量与研究边界。
5. 执行 `python3 -m unittest discover -s tests -p 'test_lemo*.py'` 和 `python3 -m unittest discover -s tests -p test_new_sources.py`，用新增用途实际search/inspect，再实际get一个新增风格。验证空输入、坏版本、坏源码、缺卡与越界引用会在消费者路径被拒绝。
6. 在新项目按 `search → inspect → get → 改编短样 → 全片` 使用。项目回执固定自己的版本；后续库升级不改旧项目缓存和已交付片。维护候选不会执行上游代码、安装全局插件或自动采用新生产框架。

新增8项主要是剪辑与纪实语法：字幕新闻、新闻影片、实时倒计时分屏、延时交响、视觉调查、体育战术讲解、构成主义蒙太奇、电视新闻包装。它们强调真实资料、时钟同步、阅读层级和声音结构，不能作为八种通用画面皮肤套在所有宣传片上。`MY-STYLES.md` 的自建风格流程则强调基底与借用来源、变更理由、可运行短片及风格帧；学的是可验证的创作约束，不是堆更多选项看板。
