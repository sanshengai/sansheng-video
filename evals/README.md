# 计划阶段评测

三个用例只做到制作单与时间线，不渲染、不联网，几分钟就能跑完。目的是看弱一点的模型照着 `SKILL.md` 能不能走对路，而不是评成片好坏。

| 用例 | 考什么 |
|---|---|
| `article-to-feed` | 文章转 30 秒抖音竖屏知识片：写出能通过检查的新作制作单（开头 3 秒不豁免），时间线通过校验，可读性提示已处理或写了理由 |
| `promo-series` | 在已认可样板上扩成 3 条系列：系列制作单列出全部 3 条，「已认可组合」沿用样板，第 1 条时间线通过校验 |
| `local-caption-fix` | 已有工程改一句字幕：写修订卡、不另写新制作单，时间线只改那一句 |

## 怎么跑

1. 给被测 Agent 一个空的输出目录、`SKILL.md` 的路径和 `cases.json` 里该用例的 `task` 与 `input`（或 `input_files`），让它按 Skill 自己决定读哪些文件。
2. 跑完后评分：`python3 evals/score_case.py <用例 id> <输出目录>`，全部检查通过时退出码为 0。
3. 同一用例用强、弱两个模型各跑一遍。弱模型没过的项，说明 Skill 写得不够清楚：回去改文档或把规则做成检查，不放宽评分。

`fixtures/profile.json` 是评分用的中性 profile，只含竖屏信息流平台清单。
